# TypeScript: Why and How

## Why This Matters

TypeScript is JavaScript with types. It catches bugs before your code runs — not at 3 AM when a user reports a crash. Every major framework (Next.js, React, Angular) has first-class TS support. In 2026, TypeScript isn't optional — it's the standard.

## Core Concepts

### The Problem TypeScript Solves

```javascript
// JavaScript — no error until runtime
function greet(name) {
  return "Hello, " + name.toUpperCase();
}
greet(42); // TypeError at runtime: 42.toUpperCase is not a function
```

```typescript
// TypeScript — catches this before you even run it
function greet(name: string) {
  return "Hello, " + name.toUpperCase();
}
greet(42); // ❌ Compiler error: Argument of type 'number' is not assignable to 'string'
```

### Setting Up TypeScript

```bash
npm init -y
npm install -D typescript @types/node
npx tsc --init          # creates tsconfig.json
```

Key `tsconfig.json` settings:

```json
{
  "compilerOptions": {
    "strict": true,          // enables ALL strict checks
    "target": "ES2022",      // output JS version
    "module": "ESNext",      // module system
    "outDir": "./dist",      // compiled output folder
    "rootDir": "./src"       // source folder
  }
}
```

### .ts vs .js

- `.ts` — TypeScript source files
- `.tsx` — TypeScript with JSX (React/Next.js)
- `.js` — plain JavaScript output (generated by `tsc`)

### How TS Works

```
TypeScript source (.ts)
        ↓
    tsc (compiler)  ← catches type errors here
        ↓
JavaScript output (.js)  ← runs in browser/Node.js
```

TypeScript types are **erased** at compile time — they exist only during development.

### Your First TS File

```typescript
// hello.ts
function greet(name: string): string {
  return `Hello, ${name}!`;
}

const message = greet("TypeScript");
console.log(message);
```

```bash
npx tsc hello.ts     # compiles to hello.js
node hello.js        # Hello, TypeScript!
```

### Why Strict Mode Matters

Always use `"strict": true`. It enables:
- `strictNullChecks` — catches null/undefined misuse
- `noImplicitAny` — forces explicit types
- `strictFunctionTypes` — prevents unsafe function assignments

Without strict mode, TypeScript is just JavaScript with extra steps.

## Try It Yourself

1. Create a TypeScript project with `tsc --init` and `"strict": true`.
2. Write a function that adds two numbers with proper type annotations.
3. Deliberately pass a string where a number is expected — see the compiler error.
4. Compare the compiled `.js` output with your `.ts` source.

## Common Mistakes

- **Not enabling strict mode**: Without it, TypeScript misses many real bugs. Always `"strict": true`.
- **Ignoring compiler errors**: Red squiggles are bugs. Don't ship code with TS errors — use `// @ts-ignore` only as a last resort.
- **Over-typing**: Not everything needs an explicit annotation. TypeScript infers types well. `let x = 5;` is fine — no need for `let x: number = 5;`.
